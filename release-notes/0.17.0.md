## Security

- Apps that are not privileged now run under AppArmor, Docker's standard confinement on Debian and Ubuntu hosts: no mounts, no writes to the sensitive parts of `/proc` and `/sys`. Apps with privileged access in their project are not affected. An app that mounts something without privileged access needs that access from now on.

## New

- PCs show IronFlock's logo while they start, instead of boot messages, and keep it on the screen until an app shows its own picture. A device can show its own picture and background colour instead: an app with access to the screen puts `splash.png` and `splash.conf` into `/data/ironflockos/screen`, and the next start shows them. What the device has to tell a person at the screen, for example that it is not enrolled, appears below the picture.
- The usual keys work at the screen: Esc during the first two seconds shows the boot menu, with "Start with messages" and "Firmware setup"; Esc while it starts shows the messages; Ctrl+Alt+F2 to F6 give a login prompt and Ctrl+Alt+F1 leads back. A console password for the device's user can be set in `/data/ironflockos/console-password`; without it nobody can log in at the screen, as before. SSH stays key-only.
- `ironflock` 2.1.0 is in the image.

## Changed

- A device that was switched off without shutting down repairs its data partition at the next start when the usual quick check gives up, instead of starting without it.
- The screen, the boot menu and the repair at start come with a new installation. A device installed with an earlier release gets AppArmor and `ironflock` 2.1.0 with the update and keeps the text screen.
